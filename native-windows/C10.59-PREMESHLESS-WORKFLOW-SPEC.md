# AsterMax Mechanical C10.59 — Geometry-first setup / run-time meshing

## User-observed defects
- Default material creation can surface: `The name can not contain space characters: 'Acero estructural - AsterMax'.`
- Current workflow couples material/section/contact setup to FE mesh availability, making setup unnecessarily slow.
- Concentrated load components shown as F1/F2/F3 are ambiguous.
- Orientation triad is visual only; user requires clickable orthographic X/Y/Z views.
- Long STEP/import and solve operations need explicit foreground progress feedback instead of looking frozen.

## Required workflow contract
1. STEP import produces CAD bodies and a lightweight geometry representation only. No volume FE mesh is required for normal model setup.
2. Immediately after successful STEP import, ensure exactly one canonical default material named `Acero_Estructural` (identifier contains no spaces) and attach a geometry-level pending material assignment to every imported solid body.
3. Default material properties are editable reference data. Do not claim a certified steel grade without user verification.
4. Material assignments and contact definitions are stored against stable CAD/body/face identities before meshing. FE element/section expansion is deferred.
5. User can configure analysis type, loads, boundary conditions, contacts and materials while the model remains unmeshed.
6. Run preflight order:
   - validate geometry-level material assignments;
   - validate BC/load/contact references;
   - if mesh is missing or stale, generate mesh;
   - project geometry-level material/section assignments and contact references to generated mesh;
   - require zero unassigned elements and zero multiply assigned elements;
   - export Code_Aster model;
   - run native Windows Code_Aster;
   - load results.
7. If a valid current mesh already exists, Run must reuse it. Any geometry or mesh-control change marks the mesh stale.
8. UI remains responsive during meshing/solve and reports explicit phases: `Preparando`, `Mallando`, `Validando`, `Resolviendo`, `Resultados`.
9. Load editor labels global components `Fx`, `Fy`, `Fz` instead of `F1`, `F2`, `F3`. For non-global coordinate systems, show axis-aware labels or the coordinate-system name.
10. Orientation triad X/Y/Z is interactive: clicking an axis requests an orthographic view normal to that axis and fits the current visible model. Preserve existing ribbon Isometric/Fit commands.
11. Do not trigger full tree rebuild, edge extraction, camera reset, or render per body during default assignment. Batch model mutation and refresh once.

## ANSYS-like foreground progress UX
### Geometry import dialog
- Opening/importing STEP/IGES/BREP shows a dedicated non-freezing progress window immediately.
- Window contains: operation title, current phase, progress bar, numeric percent when measurable, elapsed time, estimated remaining time when statistically defensible, current body/total bodies when known, and a scrolling detail/status line.
- Import phases are instrumented rather than simulated: `Leyendo archivo`, `Interpretando CAD`, `Procesando cuerpos`, `Generando vista previa`, `Autoconfigurando material`, `Preparando árbol`, `Finalizando`.
- Progress is based on completed measurable work units (bytes only where meaningful, bodies, CAD jobs, actors, model mutations). Never advance a fake timer merely to animate the bar.
- ETA is shown only after enough samples exist. Use rolling throughput from completed work units; otherwise display `Estimando...` or `Tiempo restante: calculando`.
- ETA must be monotonic-smoothed enough to avoid jumping wildly and must never claim precision that backend events do not support.
- If a backend phase exposes no measurable denominator, switch that phase to indeterminate/marquee while still displaying elapsed time and live phase text.
- Cancellation is offered only for phases that can be safely cancelled; otherwise button is disabled with explicit status.
- On success dialog reaches 100%, records elapsed time, closes automatically after a short UI handoff, and focuses the imported model. On failure it remains open and exposes the real error/diagnostic path.

### Run / solve dialog
- Pressing Run opens a dedicated progress window before any expensive preflight/mesh/solver operation.
- Required visible pipeline: `Preparando modelo` -> `Mallando` (only if missing/stale) -> `Asignando materiales/secciones` -> `Preparando contactos` -> `Validando modelo` -> `Exportando Code_Aster` -> `Resolviendo con Code_Aster` -> `Leyendo resultados` -> `Finalizando`.
- Overall percent is a weighted aggregation of real completed phases/work units. Phase weights may adapt to whether meshing is required; do not report a fabricated solver percent.
- During NetGen meshing, report measurable job/body completion where available plus elapsed/ETA; if NetGen provides no granular progress for a single job, use indeterminate progress for that job rather than fake percentages.
- During Code_Aster execution, parse trustworthy stdout/message/status milestones into human-readable live text (for example current analysis/solver stage) and retain the raw tail in an expandable `Detalles` area.
- If Code_Aster does not expose a reliable denominator, solver phase remains indeterminate while overall pipeline can still show completed-stage progress. Never infer convergence or percent from CPU time alone.
- Display elapsed time continuously. ETA appears only when supported by observed throughput/history for the current measurable phase; otherwise `Calculando...`.
- Provide `Cancelar` only through the existing safe cancellation lifecycle; cancellation must terminate/clean worker processes and leave the model in a coherent state.
- UI thread must not block while import, meshing or solver workers run. Progress events are marshalled to UI at a throttled cadence to avoid render/message-pump flooding.
- The progress window must not trigger model-tree rebuilds, camera resets or viewport renders on every progress event.
- Completion state distinguishes `COMPLETADO`, `CANCELADO`, `FALLÓ` and `BLOQUEADO`, and links to diagnostics for failure/block states.

## Telemetry contract
Record timings separately for CAD read, body processing, preview/actor creation, default assignment, tree refresh, meshing, post-mesh assignment, validation, Code_Aster export, Code_Aster execution and result loading. These timings are evidence for future ETA calibration and performance work; they are not hard-coded benchmark claims.

## Acceptance gates
- Importing a STEP does not require a volume mesh before adding loads/BC/material/contact definitions.
- `Acero_Estructural` is created/selected without invalid-name exceptions and all imported solids have one pending default assignment.
- Import progress dialog appears immediately, stays responsive, reports real phases and never fabricates percent/ETA.
- Run with no mesh visibly enters meshing before solve; Run with a valid mesh does not remesh.
- Run progress dialog exposes real pipeline stages, elapsed time and Code_Aster status without fake solver percentages.
- Post-mesh preflight reports `elements_without_section=0` and `elements_with_multiple_sections=0` before solver launch.
- Load UI uses Fx/Fy/Fz for global Cartesian components.
- Clicking X, Y, or Z triad yields the corresponding orthographic camera orientation.
- No periodic localization timer is reintroduced.
