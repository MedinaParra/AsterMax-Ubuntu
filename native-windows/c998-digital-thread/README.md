# AsterMax C9.98 — Active-model results identity gate

## Increment

C9.98 closes a result-integrity gap in the Windows PMV. A real Code_Aster MED-derived result bundle is no longer sufficient by itself: before AsterMax accepts it for visualization, the bundle must carry the SHA-256 fingerprint of the exact `FeModel` that produced it, and that fingerprint must match the currently active model.

The fingerprint is generated by the existing C9.76 canonical model fingerprint contract, which includes the mm/N/MPa unit system, mesh node coordinates and connectivity, material data, analysis steps, boundary conditions, and loads.

## Safety / evidence contract

- `bind-c998-results-fingerprint.py` performs metadata-only binding.
- It refuses bundles not explicitly marked `fea_values_invented=false`.
- It validates a strict 64-hex SHA-256 model fingerprint.
- It hashes the `arrays` subtree before and after binding and fails if the FEA arrays changed.
- The Windows Results Workspace recomputes the fingerprint from `_controller.Model` and rejects the bundle as `STALE` when the fingerprints differ.
- Node and element counts are also checked as a secondary mesh identity guard.

C9.98 does **not** claim ANSYS numerical equivalence and does **not** generate new displacement or stress values.

## Remaining professional gaps

1. The Solve command still needs a native transaction that automatically exports the active `FeModel`, executes Code_Aster, captures solver provenance, converts MED, binds the active fingerprint, and pushes the accepted result directly into the VTK workspace without a manual JSON load step.
2. STEP import identity should be captured automatically from the real imported CAD object/file rather than only through external preflight/fidelity harnesses.
3. The current production solver/export scope remains deliberately narrow around the validated linear-static HEXA8 route.
4. Professional meshing still needs broader element-family support, local sizing/refinement controls, and validated quality metrics.

## Next priority

C9.99: implement a single-session `Solve -> verified Code_Aster transaction -> fingerprint-bound results -> VTK` coordinator. The coordinator must mark previous results stale immediately after model mutations and must refuse visualization if solver provenance, model identity, or unit contracts do not match.
