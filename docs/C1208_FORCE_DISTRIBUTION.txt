C12.08 local candidate: explicit nodal-force interpretation

Base: c5b278f009d7ce346a0b745ab04cb5b4e7a68698. Not a released Windows build.

The concentrated-force editor offers PorNodo and TotalUniformePorNodo.
PorNodo applies each entered component to every selected node. TotalUniformePorNodo
interprets the components as the total resultant and divides by the CURRENT number
of unique selected nodes at export. This is uniform nodal loading, not pressure
or area-weighted loading. Changing the mode retains the entered numbers and
explicitly changes their interpretation; it does not numerically convert them.

Existing serialized CLoad objects and newly created default loads remain per-node.
Explicit totals use a distinct serializable CaeModel.UniformTotalCLoad subtype,
accepted by StaticStep. No serialized fields are added to existing CLoad or Load.
An older executable cannot resolve the new subtype; this is preferable to silently
reading a total as a per-node force. New total-mode files require the new build.
The independent non-Code_Aster keyword writer rejects this subtype rather than
reinterpreting it. This guard does not execute or substitute any other solver.

The native bridge emits explicit nodal_force_total plus
distribution=UNIFORM_PER_SELECTED_NODE for the new type. Existing CLoad still emits
nodal_force_per_node. Legacy JSON total contracts retain their previous numerical
interpretation and LEGACY_TOTAL_DISTRIBUTED audit label.

The UI preview and exporter use the same production force planner. Before launching
Code_Aster the preview shows current node count, per-node vector, resultant vector,
and the actual number of CONTINUE ContactPairs and bonded Tie constraints. A
multi-node per-node load is explicitly warned about. Cancel is the default choice.
Existing internal automated audit mode bypasses the dialog, not the validation.
The preview explains that an executable upgrade does not convert saved contacts.

Empty selections, duplicate selected IDs, missing mesh IDs, duplicate mesh IDs,
non-finite components/resultants, incompatible units, mixed total/per-node fields,
type/field contradictions and unsupported distributions are rejected before files
are created. Duplicate selection entries are diagnosed, not silently removed.
The load plan never edits input, excludes nodes, changes area/pressure definitions,
or changes force magnitudes in an existing model. The .comm numeric formatter now
uses round-trip precision, including very small nonzero forces.

Selection changes cause the total-mode division to be recomputed. Existing
fingerprinting already includes mesh group membership, load runtime type and
public enum properties; the new mode and changed selection invalidate old results.
Old per-node force resultants still change with node count, intentionally.
The mesh IDs used here are current FE identities, not persistent CAD identifiers.
