# Security policy

Please avoid publishing exploitable security details in a public issue before maintainers have had a reasonable opportunity to assess them. Report suspected vulnerabilities privately through the repository owner's available private security-reporting channel when enabled.

Security reports should include the affected version/commit, reproduction steps, impact, and any proposed mitigation. Do not include customer confidential data, credentials, proprietary third-party binaries, or restricted material in a report.

Engineering correctness issues that could create unsafe analysis results should be treated with the same seriousness as conventional software vulnerabilities: preserve the failing model, solver/runtime version, logs, mesh/BC/material inputs, and the exact result discrepancy.
